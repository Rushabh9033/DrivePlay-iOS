## Gotchas learned
- A web view with **no window at all** still renders — five of five good
  pictures, 11–21 ms each, and a layout viewport of exactly 1280×720 (a
  window-hosted one lays out at 1280×639 and cuts the page off).
- The picture is **three times** the view: `takeSnapshot` gives 3840×2160 px
  while `image.size` says 1280×720 points. Mixing the two samples the wrong
  place entirely.
- The encoder's canvas and the web view's layout **disagree about which way
  is up** — Core Image is bottom-up, the page is top-down.
- The share's `tearDown()` calls `stopScreenShare()`, so the phone's share
  must be stopped **before** the car's browser takes the player.
